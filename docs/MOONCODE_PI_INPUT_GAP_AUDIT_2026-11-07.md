## 续优化：修掉默认工具失败，而非再删必要上下文

继续只使用已有日志和本地执行器，不付费重跑。原第三轮 `moon_cmd` Native 与第十轮 Git 的 `xcode-select` 错误可在本机原样复现，不能只归为模型没有抄全环境变量。

Fort 已允许 `/private/var/select` 和实际开发工具目录，却没有允许查询 `/var` 系统别名的元数据。系统工具选择器因此把路径解析失败报为 `Operation not permitted`，不能进入正常的默认工具选择。离线对照中，仅补 `/var` 的 `file-read-metadata` 即让默认 clang 成功；只允许最终 `/var/select/developer_dir` 仍失败。Git 随后暴露宿主 `/etc/gitconfig` 拒绝，系统 attributes 也会产生重复警告。

生产修改仅在已有 Fort macOS policy/environment **增加三行**：允许 `/var` 本身的路径元数据，并设置 `GIT_CONFIG_NOSYSTEM=1`、`GIT_ATTR_NOSYSTEM=1`。没有继承宿主环境、读取额外目录、发现工具链或增加重试。保留一个真实系统 Git/clang 回归，删除临时诊断测试；删去默认 Native 必须逐次补 Shell 环境的过时配置说明。
