# MoonCode / Pi 输入 benchmark

2026-11-08。**当前样本的主要额外输入是工具 schema 和完整 Skill；历史正文累计携带反而少于 Pi。1.32 倍仍是固定轨迹的本地计数，不能称为改动后真实交付成本。** 本轮不调用 provider，未根据构造的补读路径修改运行时。

## 样本、方法与可验证范围

- 使用同一真实 bug 的两套成功轨迹，各 12 次模型响应。Pi 读取原请求；MoonCode 在运行时代码 `349b3933` 上重新经过真实的消息构建、工具选择、结果投影和 context compiler，冻结原行动。
- 主 benchmark 1 次预热＋7 次测量，共 96 帧。8 次连续回放均为 **62,544 token**，检查完整 Skill、编辑原文、最终测试结论和工具可用性；同一请求内完全相同的消息重复成本两边均为 **0**。
- 统一使用现有 cl100k 计数器，分项和逐轮总量严格相加。另对两套原请求比较真实 usage，校验计数口径。原始日志三份哈希复核通过；旧费用和失败记录保留。
- 这是**输入构建与计数 benchmark**，不是新模型的自主交付 benchmark。Pi 当前运行时未重跑，模型选择和新的返工／质量／往返未测。上一轮人为插入的目录查询、正文补读和恢复请求不纳入主 benchmark。

## 实际 usage 与估算不能混用

| 原成功轨迹，各 12 请求 | 原请求本地计数 | 原 provider input | 估算偏差 | 已记录缓存读取 |
| --- | ---: | ---: | ---: | ---: |
| MoonCode 原版本 | 132,150 | 124,777 | +5.91% | 18,176 |
| Pi 原轨迹 | 47,355 | 45,950 | +3.06% | 16,000 |

132,150 对应付费轨迹的原 17 工具／原消息，不是此前各个优化版本的中间基线。最新 MoonCode 的 **62,544 没有对应的新 provider usage**，缓存和实际费用也未知。不能把上述偏差按比例套到新版，更不能把 1.3208 当成真实费用或自主交付成本比。

### 工具签名究竟贵在哪里

按同一列表的有序增量计数，不能把独立删字段的边际量相加：

| schema 分组 | 当前 MoonCode | Pi |
| --- | ---: | ---: |
| read / write / edit / shell（Pi 为 bash） | **5,160**（430×12） | **7,188**（599×12） |
| ask_user / read_result / read_skill / finish | **3,900**（325×12） | 0 |
| moon_cmd / moon_ide，加载后 11 请求 | **4,070**（370×11） | 0 |

基础四工具的签名体积已经更小。当前差额主要来自额外能力暴露，不能继续归因于四个基础 schema 写得太长。此处只比较输入体积，不宣称两边执行语义或权限相同。

### 历史正文并非仍比 Pi 多

| 工具正文计数 | 当前 MoonCode | Pi |
| --- | ---: | ---: |
| 每份结果首次出现 | 5,187 | 2,646 |
| 同一结果之后重复携带 | **12,129** | **19,751** |
| 合计 | 17,316 | 22,397 |

MoonCode 的后续正文携带比 Pi **少 7,622**。整份测试只在第 3 轮出现一次，**2,348**，后续携带为 **0**。outline 为 331 首次＋1,655 后续；源码为 864＋4,320；原 Native 配置失败为 612＋4,284。结果级明细保留每次出现的轮号，未删除历史失败来降低数值。

### assistant 差额主要落在编辑参数

assistant 差额 2,297＝参数 **1,844**＋调用 ID **396**＋函数名 **57**；双方普通 assistant 正文均为 0。两边都发起 3 次 edit，其参数在历史中的累计输入为 **3,854 vs 2,246，差 1,608**。这是实际匹配／替换内容与修改粒度的差异，不是已测出的新版本模型返工减少，也不能直接声称改一句 prompt 就能省下它。

原轨迹 MoonCode 的 Skill 加载 **1 次**；目录查询 **0**、工具包查询 **0**、`read_result` **0**。Pi 这些调用均为 0；双方模型响应都为 12 次。因此没有数据证明这条轨迹的差额由按需加载新增往返造成。

## 实际消融：删 finish schema 反而增加输入

复用已有文本答复→内部 finish 适配，隐藏默认 finish schema，并同步调整主提示。末次 function 答复机械转换为相同文本，验证内部 finish 的答案字节不变；其余行动冻结，完整指令、编辑依据和最终结论保留。此消融单列，不当成新模型观测。

| 连续回放分项 | 基线 | 消融 | 增减 |
| --- | ---: | ---: | ---: |
| schema | 13,130 | 12,506 | −624 |
| 主提示／索引 | 4,332 | 4,296 | −36 |
| 结果头 | 8,093 | 8,288 | +195 |
| 正文 | 17,316 | 18,511 | +1,195 |
| 其他分项 | 19,673 | 19,673 | 0 |
| 总计 | **62,544** | **63,274** | **+730** |

新增正文精确来自 outline **+331**、源码 **+864**，各多保留一轮。减少固定输入后，既有压力投影延后了这些结果的省略；不是猜测的“可能被历史填回”。**候选已恢复，没有合入。** 更小 schema 的静态数值不能代替完整回放净收益，也不能据单个固定轨迹判断真实模型更少补读的收益。

## 本地耗时与验证

Native debug，预热 1 次后测量 7 次，每次包含 12 帧：compiler 合计中位数 **343 ms**、P95 **636 ms**；完整夹具回放（含文件 I/O、断言和额外计数）中位数 **631 ms**、P95 **1,194 ms**。7 个原始样本全部保留，P95 按 nearest rank，样本较少时就是最大值；未剔除较慢样本。首轮回放 740 ms，不是应用冷启动。这里没有 Pi runtime 延迟或 provider 延迟比较。

主 benchmark、finish 消融及其分项校验分别 Native **1/1**。所有临时测试和依赖修改已清除，运行时代码不变；本轮没有重跑或重新声称全量 Native 1837 项结果。
