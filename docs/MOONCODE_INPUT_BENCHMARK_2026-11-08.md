# MoonCode / Pi 输入 benchmark

最新实现见[源码修复与复测](#源码修复与复测)：输入构建连续回放 **60,749**，固定轨迹约 Pi 的 **1.2828 倍**，不是新的 provider 计费。以下先保留修复前 benchmark，再记录代码、窗口与全部失败组。

## 修复前基线

2026-11-08。**当前样本的主要额外输入是工具 schema 和完整 Skill；历史正文累计携带反而少于 Pi。1.32 倍仍是固定轨迹的本地计数，不能称为改动后真实交付成本。** 本轮不调用 provider，未根据构造的补读路径修改运行时。

## 样本、方法与可验证范围

- 使用同一真实 bug 的两套成功轨迹，各 12 次模型响应。Pi 读取原请求；MoonCode 在运行时代码 `349b3933` 上重新经过真实的消息构建、工具选择、结果投影和 context compiler，冻结原行动。
- 主 benchmark 1 次预热＋7 次测量，共 96 帧。8 次连续回放均为 **62,544 token**，检查完整 Skill、编辑原文、最终测试结论和工具可用性；同一请求内完全相同的消息重复成本两边均为 **0**。
- 统一使用现有 cl100k 计数器，分项和逐轮总量严格相加。另对两套原请求比较真实 usage，校验计数口径。原始日志三份哈希复核通过；旧费用和失败记录保留。
- 这是**输入构建与计数 benchmark**，不是新模型的自主交付 benchmark。Pi 当前运行时未重跑，模型选择和新的返工／质量／往返未测。上一轮人为插入的目录查询、正文补读和恢复请求不纳入主 benchmark。

### assistant 差额主要落在编辑参数

assistant 差额 2,297＝参数 **1,844**＋调用 ID **396**＋函数名 **57**；双方普通 assistant 正文均为 0。两边都发起 3 次 edit，其参数在历史中的累计输入为 **3,854 vs 2,246，差 1,608**。这是实际匹配／替换内容与修改粒度的差异，不是已测出的新版本模型返工减少，也不能直接声称改一句 prompt 就能省下它。

原轨迹 MoonCode 的 Skill 加载 **1 次**；目录查询 **0**、工具包查询 **0**、`read_result` **0**。Pi 这些调用均为 0；双方模型响应都为 12 次。因此没有数据证明这条轨迹的差额由按需加载新增往返造成。

## 本地耗时与验证

Native debug，预热 1 次后测量 7 次，每次包含 12 帧：compiler 合计中位数 **343 ms**、P95 **636 ms**；完整夹具回放（含文件 I/O、断言和额外计数）中位数 **631 ms**、P95 **1,194 ms**。7 个原始样本全部保留，P95 按 nearest rank，样本较少时就是最大值；未剔除较慢样本。首轮回放 740 ms，不是应用冷启动。这里没有 Pi runtime 延迟或 provider 延迟比较。

主 benchmark、finish 消融及其分项校验分别 Native **1/1**。所有临时测试和依赖修改已清除，运行时代码不变；本轮没有重跑或重新声称全量 Native 1837 项结果。

## 源码修复与复测

继续查源码后，合入三项契约／表示收敛，沿用原执行器、资源身份、grant、journal 和 context compiler：

1. **edit 只保留 `edits[]`**。删除顶层 old_string/new_string/replace_all 与数组的并存拼接逻辑，单次编辑也是一项数组；仍按序验证、一次原子写入，单项 `replace_all` 保留。已有调用方和行为回归迁移，删除重复的混合格式用例。
2. **moon_cmd 只保留 `args[]`、`paths[]`**。删除 arg/path 标量别名、对应拼接代码及两个无调用者的收集函数；删除 test_update_kind/reason schema、必填理由门槛和空 metadata。更新快照仍经过原 grant／资源边界，`--update` 的调度属性保留。没有新增兼容分支。
3. **Skill 指令与路由元数据分开**。复用已有 YAML parser，长期前缀只携带完整 Markdown 指令正文；name/description/license/allowed-tools 留在 registry 和完整 canonical 资源。引用资源、普通文本、自定义或未知 frontmatter 原样保留。完整原文件仍能从 journal 回取；不做摘要或额外模型调用。

旧日志参数只在离线夹具中机械迁移成新数组形状，保留每项 old/new 文本、顺序、replace_all、expected_exit_code；SDK 编译出的 argv 精确核对仍为 `moon test --target native --frozen pathx`。没有把历史失败改写成成功、没有裁剪代码参数，也没有把这次 ABI 迁移当成新的模型选择。工具能力数量仍为默认8、加载 MoonBit 后10、完整工具包13。
