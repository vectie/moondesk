# Turn selected CSV or spreadsheet rows into a Markdown table

1. Open a Markdown file in MoonDesk's source editor.
2. Paste CSV text or tab-separated spreadsheet rows. Include a header row.
3. Select just the data block, including complete quoted/multiline fields.
4. Under **Selected data**, choose **CSV → Markdown table** or
   **TSV → Markdown table**.
5. Review the selected table. **Undo** restores the original data in one step;
   **Redo** restores the table. **Save** uses the normal source-file workflow.

The controls capture the current textarea selection. Conversion preserves text
outside it, inserts blank-line boundaries around the table, and selects the
result. It works with Unicode and the ordinary per-tab edit history. Loading,
unavailable, and saving files cannot be converted.

Try [status-source.md](samples/table-import/status-source.md): select from
`Item,Owner,Notes` through the closing quote after `checked`, then use CSV.
The result is [status-table.md](samples/table-import/status-table.md).
The synthetic sample includes a comma inside a cell, a quoted newline,
Unicode, and a pipe that must remain inside its cell.

The first record is the header. Each row must have the same number of fields;
blank records are not dropped. Both CSV and TSV support double-quoted fields
and doubled quotes inside them. An error names the record/field to fix and
leaves your selection and draft intact. Select the correct delimiter explicitly.

Cells become literal text: Markdown formatting is escaped, spaces and pipes
use entities, and embedded newlines become `<br>`. A pipe-table renderer with
entities and inline HTML supports the intended display. Source text can look
more verbose than the rendered table. This does not read `.xlsx` files, execute
formulas, infer missing headers, or preserve spreadsheet styling/merged cells.
To insert a clipboard table, paste normally first and select those new rows;
there is no new clipboard access. The checked-in distribution bundle is not
regenerated by this source change; build the UI before running it.

## Focused verification

With the existing sibling MoonEdit/MoonLeaf workspace and dependencies:

```text
moon test main/source_table_import_wbtest.mbt --frozen --target js --strip -j 1
```

The opt-in `main/source_table_import_live_wbtest.mbt` test opens `status.md`,
converts, undoes/redoes, saves, closes, and reopens through actual HTTP. Run it
only with an isolated native host containing `books/table-demo/status.md`
copied from the input sample. Set `MOONDESK_LITERAL_HOST_ORIGIN` to that
loopback origin and `MOONDESK_LITERAL_WORKSPACE` to its returned workspace ID,
then add `--include-skipped` to the focused test command. It changes that fixture.
Compiled controller/render checks are not a graphical-browser or accessibility
qualification. Filesystem permissions and ordinary save/conflict behavior remain
owned by the existing host.
