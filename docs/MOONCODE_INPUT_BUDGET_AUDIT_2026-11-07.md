# MoonCode：93 万 input 的逐轮构成（2026-11-07）

后续生产修复和 OpenSeek/Pi/DSH 输出对照见[资源与框架对比](MOONCODE_RESOURCE_AND_FRAMEWORK_COMPARISON_2026-11-07.md)：收敛快照留存范围；完整共同模型交付对比仍待运行条件。

**主要来源是一次越过输出上限的 grep 结果在后续请求中反复出现，其次是额外轮次反复携带固定提示、工具定义和已读源码。** 前一份报告的 0.47% 只度量删除旧提示和错误索引去重，不能代表主要缺陷修复的收益。

本轮只读取已有日志和 receipt，执行本地 tokenizer 与真实上下文构造函数；没有启动付费模型、MoonCode canary 或真实 grant publisher / 执行器。既有本地回归沿用测试 fixture。历史实际成本仍为 **935,131 input / 6,169 output，35 次响应**，其中 cached input 84,224。协调对话和本地编译/测试另有资源成本。

## 口径

- **实际 input**：按 command 关联 journal 中唯一 model_response_id 与 planner_metrics，三段分别为 636,327、158,159、140,645；不扫描输出内嵌的 prompt_tokens 文本。
- **组成估算**：把 provider 可见消息交给已有 `token_counter.Counter::count_message`，工具定义使用其 cl100k tokenizer 编码原 JSON。工具正文按“完整消息减去空 output 消息”计算，剩余为 envelope；不重复计入。
- 本地合计 **954,652**，比 provider input 高 **19,521（2.09%）**。tokenizer、schema 编码和 API framing 不等同 provider 计费；下列组成和反事实都采用本地口径，不把估算比例套成精确账单。
- 三段使用同一组 17 个工具，schema 均为 10,672 字符。当前工具定义及其构造与实跑前 `22176639` 无变化；本地每轮 schema 估算为 2,268。消息按角色和来源分类，`read` 正文实际来自 path.mbt / path_test.mbt。

## 最大问题的真实 receipt 回放

原调用请求 `max_output_chars=20000`。grep 递归进入 `.moonsuite`，匹配到包含旧工具输出和请求历史的单行 journal；`head -100` 限制行数，无法限制单行长度。Fort 因 output-limit 返回 Killed，完整输出 artifact 为 10 MiB，receipt.output 为 **260,256 字符**。

旧转换器在非 Exited 分支提前返回 raw output，绕过调用者上限。**`76ceaa86` 已将原有截断移到状态分派之前**，无需另加预算、压缩器或错误策略。本轮直接读取原始 receipt，调用当前 `mooncode_sandbox_terminal_result` 和真实模型结果投影；结果仍为失败，保留 evidence_ref 与完整 output_artifact 引用，output 不超过 20,000 字符。

本轮另外用真实 follow-up producer 连续回放全部 35 次请求。每轮继承上一轮候选 model_messages，不重新换回原始历史。除这六份已限长观察、删除的旧提示和索引去重外，其他消息、调用 ID、任务、工具结果与读取路径保持一致。原动作和模型回复被冻结，**没有声称已减少响应次数，也没有把 441,848 当成新实跑成本**。

## 无效往返放大了剩余成本

1. **B7、B8、B9、B10、B12、B13、B14 七次快照创建失败，发起轮次合计 83,360 实际 input。** 首次失败后，B8/B9/B10/B12/B13/B14 六次重试合计 **72,734**。失败发生在测试进程启动前，换测试命令、目标目录或 `true` 都没有修复前置快照；同一源码/测试和固定前缀仍随每次请求重复发送。原 `storage-io` 丢失底层原因的问题已在 Fort `4c389a0` 修复，但本轮不能证明恢复错误详情后模型一定少重试。
2. **B11、C2 两次超时参数拒绝，发起轮次合计 22,275 实际 input。** 两个命令当时都未看到上限反馈；schema 没有动态部署 ceiling。不能把两次都归为忽略同一条可见错误，也不将 600000 硬编码成通用工具常量。
3. **返工真实存在。** A4 的调用方回归、B5 的类型错误、C3/C5 的根路径错误和 C7 的调用方回归都在原日志中；之前的 12 版本源码重放已复现。源码与 replace_ext 可见，不能归为加载不足。清理过的源码重复解析不是模型推理改进的证明。
4. **额外复核真实存在，但没有运行时强制插入。** A6 已做目标/全仓测试和 Git，A7 又 Git；旧模型请求 A7 单轮高达 104,814 input，其中主要仍是那份 grep 历史。应用 cap 后同一轮约 19,929。前后快照的 `.tmp/` 状态不同，不能按命令文本缓存或假定观察相同。C9/C10/C11 又分别做目标测试、全仓测试和 Git，轮次成本累积。

35 次响应都有模型选择的动作，未发现额外 provider 自动重传或空回复重试。上述“发起失败动作的轮次成本”是定位视角，与内容构成表重叠；不能从 935,131 中直接相减，再宣称就是未来成功运行成本。按本地口径，每多一次空转，又带入约 **3,900–5,100 固定前缀＋约 4,000–4,700 源码/测试＋逐渐增长的其他历史**。
